# OWExtractor 架构

## 项目边界

| 项目 | 职责 |
| --- | --- |
| OWExtractor.App | WPF 界面、视图模型、交互编排与本地配置入口 |
| OWExtractor.Core | 资源模型、DataTool JSON 导入、既有导出清单、OWMDL 读取、导出引用路径检查、配置及任务模型 |
| OWExtractor.DataTool | 命令构造、进程管理、执行许可、输出采集及错误解释 |
| OWExtractor.Tests | 无第三方测试框架的可执行集成检查 |

业务模型和 DataTool 调用不依赖 WPF。客户端未引用 DataTool 内部静态对象，未来可以在适配层替换引擎版本。

## 两种操作路径

离线：已有英雄 JSON / 皮肤 JSON / 导出目录 → Core 导入 → 界面与配置缓存。此路径不启动引擎，不枚举游戏文件。

离线 3D：显式关联的 OWMDL → 有界网格读取器 → 导出目录内的 OWMAT / PNG → 冻结的完整模型与交互轻量模型 → WPF 预览。加载任务可取消；主视口与展开视口共享相机，展开时隐藏主视口。读取器不依赖 DataTool、Blender 或游戏存储库。

输入先合并为增量，再按 30 / 60 FPS 目标节奏更新相机；没有待处理输入时解除帧回调，隐藏、最小化及卸载时清理待处理输入。默认软件渲染在交互期间使用轻量网格和低分辨率位图，结束后恢复完整模型。轻量模型只在加载时生成，不改动源文件。可显式保存硬件优先偏好，下次正常启动交由 WPF 选择硬件或软件回退；`--software` 和所有离屏检查强制使用软件渲染。性能面板显示交互提交速率及软件绘制耗时，不把目标帧率或 WPF 能力等级当作实际 GPU 性能。

提取：用户显式启用游戏读取 → 检查游戏是否运行 → 参数适配 → 独立 DataTool 进程 → 日志及输出文件 → 任务状态。目录刷新也经过相同的执行保护。

## 进程约定

- 默认离线；启用状态只存在内存中。
- 通过参数列表传递路径与查询，不经过 shell。
- 启动前检查守望先锋进程名称；无法判断时阻止启动。
- DataTool 使用无控制台窗口、较低进程优先级，任务逐个执行。
- 取消仅终止客户端创建的引擎进程树。
- 清除继承的启动钩子和游戏路径覆盖变量，使用 `--args-reset` 避免上游保存参数混入调用。
- 不把文本日志当作精确百分比协议。只展示任务及阶段状态。

运行前的进程检查无法消除“检查后用户立即启动游戏”的竞争窗口。当前预览版要求整个提取期间保持游戏退出；运行期间持续检测与自动停止属于后续增强。

## 数据约定

英雄 GUID、显示名称和查询名称分开存储。已有中英文英雄快照通过 GUID 合并。皮肤保留解锁 GUID（若来源提供）和原始名称；只有导出目录时不伪造游戏 GUID。

皮肤查询名称暂不接受 DataTool 保留字符；无法准确表示的名称会阻止执行，避免意外扩大提取范围。

旧导出导入只读取目录和文件大小，不修改源文件，不跟随目录链接。它是本地历史结果清单，不是完整的游戏资源目录。

队列状态及输出目录持久化；应用启动时把上次未结束的任务标记为中断。重试使用新的任务子目录，旧结果保留。

## 后续演进

首先完成退出游戏后的真实闭环，记录受支持的游戏/引擎版本组合。之后补充缓存版本失效、资源语言关联和更严格的结果完整性检查。3D 当前提供静态网格与基础颜色；后续材质、装配及动画扩展保持独立于进程日志解析。
